# Employee mobile design — simplicity revision

This revision is designed for employees who prefer familiar pictures, short instructions and their own language. It changes the daily interaction model, rather than only restyling the previous tables.

## Everyday work

1. **My work:** recognize a site by its name, place and site illustration. Open it with one large button. Production should use a recognizable site photo where available; review artwork is illustrative.
2. **Your next job:** see the available work and a single large Start button. Once started, the button becomes This work is done. Other independent work remains under All work.
3. **Add photo:** open directly from the site. The device camera/gallery supplies the photo; required location permission is explicit. Send from the preview without writing a caption.
4. **Voice note:** open directly from the site. Tap to record, stop, then send. Review and re-record are separate illustrated states. No written note is required.
5. **Need material:** choose material and enter a large, clearly labelled quantity. Material names remain the administrator's names. The unit follows the selected material.
6. **Finished:** ask the manager to check. The employee sees Sent to your manager, rather than having to interpret approval terminology.

The site keeps All work, Materials and Updates as smaller secondary actions. Home navigation has My work, Messages and Help. Sending is automatic; Sync is not a primary destination employees must learn.

## Readability and feedback

- Main buttons are at least 64 px tall; main instructions and action labels use 18–30 px text. Supporting navigation is 16 px.
- Camera, microphone, parcel and work pictograms always have written labels. Color is never the only explanation.
- No site codes, approval percentages, stage counters, dependency terminology or inventory ledger language on the daily site screen.
- Daily notes remain optional. Camera/gallery photos and voice notes may be sent without a caption.
- Location is required when a photo is added, and that position survives later sending. No continuous location tracking is implied.
- The example template has plain employee labels such as Install the panels. Custom site/stage/material names remain administrator-entered content; the product must not silently translate or reinterpret those names.
- Hindi and Gujarati variants cover home, site, started work, photo location/preview, recording/review, completion, materials, requests/results, stock use/returns, updates, help, messages, profile and sending status. Remaining edge-case translation and linguistic validation are release work.

## What was checked

Automated checks validate geometry, target sizes, readable core typography, action reachability and locale-preserving destinations. Browser checks click real rendered hotspots. Requirements notes are preserved separately as review annotations; they are not forced onto the employee's screen. This is a design prototype, not an implemented GPS, recorder, stock service or offline store.

No employee usability study has been performed. A proposed field check is below; it is not a reported test result.

## Proposed field check

Use the employee's preferred language. Give each task verbally without pointing at buttons:

1. Open Suryoday solar and start the panel work.
2. Send a photo of today's work without typing.
3. Tell the manager about progress using a voice note.
4. Ask for 20 panels.
5. Tell the manager that the panel work is finished.
6. Explain what Saved on this phone means when internet is unavailable.

Observe where the employee hesitates, goes back, or asks for help. Target completion without instruction, correct site/material/quantity, no accidental duplicate submissions, and a clear understanding that the manager still checks completed work. Repeat on an actual Android/iOS device with OS permissions, outdoor lighting and intermittent connectivity before release.
